# 从项目开发到求职证据：推进与审查

本次推进的核心，是让项目中的判断、证据与结果都能被别人检查。代码量、页面数和技术名词只能说明投入；招聘者更需要看到你如何界定问题、处理不完整信息、选择方法、解释结果，并交付可复用的工具。本文件评价仓库已经形成的证据，不推断作者尚未提供的教育、工作经历或独立熟练程度。

## 能力展示：形成完整的工作样本

项目现在能够展示一条完整分析链：读取真实雇主要求，保留经验门槛和来源状态，用 SQL 汇总明确范围内的要求，将能力陈述转为可检查的作品，再在时间和预算约束下选择行动。组织案例进一步展示培训、转岗与招聘之间的资源分配。

这条链适合用来支持 People Analytics、Workforce Analytics、人才情报或研究型分析岗位的申请。它分别提供了问题拆解、来源研究、数据建模、方法评估、业务解释和产品交付的证据。岗位匹配仍需要结合具体招聘要求与真实个人经历；本次八份描述的样本不足以证明某个岗位方向有更大的市场需求。

展示时应突出三个可追问的决定：为何区分“能做”和“有证据证明”；为何保留一个表现较弱但透明的提取器；为何组织决策同时比较岗位覆盖和成本。这些问题比罗列依赖库更能体现判断力。

## 知识深度：解释构念、假设与适用范围

能力匹配并不是一个天然可靠的百分比。提取器识别的是文本片段，作品证明的是一个具体任务，岗位表现还依赖情境、互补技能与制度条件。外部 SkillSpan 测试只检验第一层，不能用来证明后面的评分有效。

实际外部结果也要求收窄宣传：测试集的技能任务上，三个基线的严格 F1 均低于 0.07；词典在另一个“技能加知识”测试任务上为 0.162。边界宽松的 overlap 指标较高，也不能替代严格匹配。保留这些结果并解释后续审核设计，可以展示测量意识；回避这些结果会削弱项目可信度。

人力资本部分需要讲清楚一般技能与特定技能、技能互补、时间机会成本、培训前提和投资收益的不确定性。系统已将课程事实、练习时间假设、培训效果与真实个人成果区分开来。组织模型的目标是优先覆盖重要岗位，然后比较增量成本；它不声称最大化企业福利，也没有估计培训的因果回报。

## 专业技能：有可复现的技术与业务工作

已完成的技术证据包括：规范化 SQLite 表与实际查询、三种提取基线的外部比较、一对一匹配评估、带优先级的整数规划、可检查的成本构成、约束与敏感性分析、表单/API/CLI 一致性、作品审核往返、自动化浏览器与干净安装验证。

30 人案例中，混合方案覆盖 12 个岗位、24 个优先级单位，现金成本 21,800 美元，情景经济成本 81,040 美元，释放培训时间 88 小时。无培训方案覆盖 10 个岗位、18 个单位。因此可以解释选择差异，不能把两个不同覆盖范围的方案直接称为节省了多少成本。释放时间从 80 到 120 小时，经济成本由 94,240 降至 81,040 美元，体现了离散培训容量的价值；培训效果降至假定值的 75% 时，完整覆盖不再成立。

这些结果支持“能够搭建和解释决策模型”的展示。它们不支持声称已经为真实企业节省成本、部署真实 HR 系统、提升就业率或掌握生产环境 Snowflake。求职材料应区分本仓库内完成的工作和将来需要真实环境验证的经验。

## 使用体验：让用户能完成任务

学习端默认展示真实历史岗位与官方资源，能够通过普通表单编辑时间、费用、准入、作品要求和技能映射。组织端提供员工同意、技能水平、补位成本、岗位优先级、空缺成本、等待期和培训座位的编辑入口。JSON 保留给导入与完整检查。

学习记录包括实际时间、作品位置、评语及四项量规；只有明确转移之后才进入重新审核。往返审核保留原课程与进度，已有否定证据不会被转成正面证据，重复转移同一作品不会重复增加证明强度。用户仍须在下一轮规划时更新剩余预算与时间，系统不会把投入时间误当成完成比例。

当前还有一个明确的证据缺口：没有真人可用性研究。独立代理审查和自动化任务回归可以发现流程错误，不能替代目标用户的理解与操作。已提供本地反馈模板、任务与记录规则。真实用户的错误解释、需要帮助的步骤和任务耗时，才是下一轮优先级的重要依据。

## 展示效果：分层展示，减少解释成本

新增 `/showcase` 将研究、测量、业务案例和限制集中在同一入口。两分钟路线展示问题、操作和结果；十分钟路线解释 SQL、指标和敏感性；深入路线允许重新运行。界面中的图表呈现实际计算结果，并把岗位样本和虚构员工情景分别说明。

README、方法、复现说明、生成案例报告和演示脚本形成不同深度的材料。面试时应先演示一个能改变结果的输入，再解释它为何改变，最后指出结论的适用范围。展示弱结果和限制需要有具体证据支撑，而不是泛泛地说“仍需优化”。

## 后续职业准备的实际顺序

第一步，独立复现项目中的 SQL 和一个手算分配例，并解释每个成本项。第二步，完成 `examples/practice` 的数据质量任务，请另一人加入新异常并检验你能否诊断。第三步，用自己的真实经历替换虚构学习者，逐项核对作品证据与岗位门槛。第四步，开展小规模真人任务观察，依据实际误解修改流程。第五步，围绕一个具体职位准备两分钟演示和三个技术追问。

这些步骤不会要求继续扩大功能范围。它们把已经完成的项目转化为本人可解释、可复现、可答辩的职业证据。AI 协助开发可以作为工作方式的一部分说明；独立熟练程度应通过复现、修改和现场诊断来证明。
